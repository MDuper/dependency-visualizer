
# Dependency Visualizer

Консольное приложение на Python для анализа и визуализации графа зависимостей пакетов npm.

Проект разработан в рамках практической работы №2 по дисциплине «Конфигурационное управление», вариант №8.

## Описание

Программа получает информацию о зависимостях пакетов из реестра npm, строит граф прямых и транзитивных зависимостей, формирует диаграмму Mermaid и сохраняет её в формате SVG.

Для получения зависимостей используются средства стандартной библиотеки Python. Менеджер npm не применяется для построения графа.

Для создания SVG используется внешний инструмент Mermaid CLI.

## Реализованные этапы

### Этап 1. Минимальный прототип с конфигурацией

Реализован интерфейс командной строки с использованием модуля `argparse`.

Поддерживаются следующие параметры:

| Параметр | Описание | Значение по умолчанию |
|---|---|---|
| `--package` | Имя анализируемого пакета | Обязательный |
| `--repo-url` | URL репозитория или путь к тестовому файлу | Обязательный |
| `--test-mode` | Использование тестового репозитория | `False` |
| `--output` | Имя выходного SVG-файла | `graph.svg` |
| `--ascii-tree` | Вывод зависимостей в виде ASCII-дерева | `False` |
| `--max-depth` | Максимальная глубина анализа | `3` |
| `--filter` | Подстрока для исключения пакетов | Пустая строка |

Реализована проверка корректности аргументов:
- Проверка имени пакета на пустое значение.
- Проверка допустимости URL репозитория.
- Проверка существования тестового файла.
- Проверка неотрицательной глубины анализа.
- Проверка расширения выходного файла `.svg`.
- Вывод сообщений при некорректных параметрах.

На первом этапе реализован вывод параметров конфигурации в формате ключ-значение.

### Этап 2. Сбор данных

Реализовано получение информации о прямых зависимостях пакетов npm.

Основные возможности:
- Отправка HTTP-запросов к реестру npm с помощью `urllib.request`.
- Получение метаданных пакетов в формате JSON.
- Определение последней версии пакета через `dist-tags.latest`.
- Извлечение прямых зависимостей из поля `dependencies`.
- Обработка ошибок HTTP и сетевого соединения.
- Обработка некорректного JSON и отсутствующих обязательных полей.

Для получения зависимостей не используются готовые библиотеки или менеджеры пакетов.

На втором этапе реализован вывод прямых зависимостей в консоль.

### Этап 3. Основные операции

Реализовано построение графа прямых и транзитивных зависимостей с помощью алгоритма поиска в глубину (DFS) без рекурсии.

Основные возможности:
- Использование стека для обхода графа.
- Ограничение глубины анализа параметром `--max-depth`.
- Исключение пакетов по подстроке с помощью `--filter`.
- Предотвращение бесконечного обхода циклических зависимостей.
- Учёт минимальной глубины посещения вершин.
- Работа с реальным реестром npm и тестовыми графами.

Тестовый режим позволяет построить граф без подключения к интернету для получения зависимостей.

Формат тестового файла:

```text
A: B C
B: D
C: D
D:
```

Каждая строка содержит имя пакета, двоеточие и список его зависимостей, разделённых пробелами.

### Этап 4. Дополнительные операции

Реализовано определение порядка загрузки зависимостей для заданного пакета.

Используется итеративный обход графа с обработкой зависимостей перед самим пакетом.

Основные возможности:
- Формирование порядка загрузки зависимостей.
- Использование стека без рекурсии.
- Предотвращение повторной обработки пакетов.
- Обработка графов с циклами.

На данном этапе вывод порядка загрузки временно добавлялся в программу для тестирования.

Результаты сравнивались с работой npm.

Порядок, полученный алгоритмом, представляет собой последовательность обхода с обработкой зависимостей перед зависимым пакетом. Он не обязательно совпадает с фактической последовательностью установки npm.

### Этап 5. Визуализация

Реализовано графическое представление зависимостей с использованием Mermaid.

Основные возможности:
- Генерация текстового описания графа Mermaid.
- Присвоение вершинам уникальных идентификаторов.
- Отображение направленных связей между пакетами.
- Отображение пакетов без зависимостей.
- Сохранение изображения в формате SVG.
- Вывод ASCII-дерева по параметру `--ascii-tree`.
- Корректная обработка общих и циклических зависимостей.

Для генерации SVG используется Mermaid CLI, запускаемый из Python через `subprocess`.

Программа создаёт временный файл `.mmd`, преобразует его в SVG и удаляет временный файл.

Изображения сохраняются в папке `output/`. При повторном использовании одинакового имени выходной файл перезаписывается.

## Запуск программы

Для запуска необходимы Python 3, Node.js и npm.

Mermaid CLI запускается через `npx`. При первом запуске может потребоваться подключение к интернету для загрузки инструмента.

Перед первым запуском необходимо сделать файл `run.sh` исполняемым:

```bash
chmod +x run.sh
```

### Запуск с реальным репозиторием

```bash
./run.sh --package debug --repo-url https://registry.npmjs.org
```

Запуск с ограничением глубины, ASCII-деревом и собственным именем SVG:

```bash
./run.sh --package express \
  --repo-url https://registry.npmjs.org \
  --max-depth 2 \
  --ascii-tree \
  --output express.svg
```

Запуск с фильтрацией:

```bash
./run.sh --package express \
  --repo-url https://registry.npmjs.org \
  --max-depth 2 \
  --filter body \
  --ascii-tree
```

### Запуск в тестовом режиме

```bash
./run.sh --package A \
  --repo-url tests/test_chain.txt \
  --test-mode \
  --ascii-tree \
  --output chain.svg
```

### Просмотр SVG

На macOS:

```bash
open output/graph.svg
```

Для просмотра справки:

```bash
./run.sh --help
```

## Тестирование

Для проверки программы подготовлены пять тестовых графов:

| Файл | Проверяемый случай |
|---|---|
| `test_empty.txt` | Пакет без зависимостей |
| `test_chain.txt` | Линейная цепочка зависимостей |
| `test_branches.txt` | Разветвлённый граф |
| `test_shared.txt` | Общая зависимость нескольких пакетов |
| `test_cycle.txt` | Циклические зависимости |

### Примеры запуска тестов

Пакет без зависимостей:

```bash
./run.sh --package A --repo-url tests/test_empty.txt \
  --test-mode --ascii-tree --output empty.svg
```

Линейная цепочка:

```bash
./run.sh --package A --repo-url tests/test_chain.txt \
  --test-mode --ascii-tree --output chain.svg
```

Разветвлённый граф:

```bash
./run.sh --package root-pkg --repo-url tests/test_branches.txt \
  --test-mode --ascii-tree --output branches.svg
```

Общая зависимость:

```bash
./run.sh --package A --repo-url tests/test_shared.txt \
  --test-mode --ascii-tree --output shared.svg
```

Циклический граф:

```bash
./run.sh --package A --repo-url tests/test_cycle.txt \
  --test-mode --ascii-tree --output cycle.svg
```

Дополнительно предусмотрена проверка фильтрации и ограничения глубины.

## Сравнение со штатными инструментами npm

Для сравнения выбраны три пакета:
- `is-number` — пакет без прямых зависимостей.
- `debug` — пакет с небольшим графом зависимостей.
- `express` — пакет с более разветвлёнными зависимостями.

### Сравнение прямых зависимостей

Команда npm для просмотра зависимостей:

```bash
npm view debug@latest dependencies --json
```

Аналогичная проверка нашей программой:

```bash
./run.sh --package debug \
  --repo-url https://registry.npmjs.org \
  --max-depth 1 --ascii-tree
```

Обе программы получают информацию из реестра npm.

При этом `npm view` показывает также ограничения версий зависимостей, а разработанный визуализатор отображает их имена и связи.

### Сравнение деревьев зависимостей

Штатная команда npm:

```bash
npm ls --all
```

Она показывает логическое дерево установленных пакетов.

Разработанный визуализатор строит граф по метаданным последних версий пакетов из реестра npm.

Возможные различия объясняются следующими особенностями:
- npm разрешает ограничения версий при установке.
- Один пакет может использоваться несколькими зависимостями.
- npm учитывает особенности фактического дерева установки.
- Разработанный визуализатор анализирует поле `dependencies` каждой последней версии пакета.
- В SVG общие зависимости отображаются единой вершиной, тогда как ASCII-дерево может содержать повторные ссылки на пакет.

Таким образом, совпадение прямых зависимостей проверяется с помощью `npm view`, а сравнение структуры дерева выполняется с помощью `npm ls --all`.

## Структура проекта

```text
dependency-visualizer/
├── src/
│   └── main.py
├── tests/
│   ├── test_empty.txt
│   ├── test_chain.txt
│   ├── test_branches.txt
│   ├── test_shared.txt
│   └── test_cycle.txt
```

Папка `output/` создаётся автоматически и содержит сгенерированные SVG-файлы. Она исключена из отслеживания Git.

## Обработка ошибок

Предусмотрена обработка следующих ситуаций:
- Отсутствие обязательных аргументов командной строки.
- Некорректные значения параметров.
- Недоступность удалённого репозитория.
- Ошибки HTTP-запросов.
- Некорректный ответ в формате JSON.
- Ошибки чтения тестового файла.
- Некорректный формат тестового репозитория.
- Ошибки запуска Mermaid CLI и преобразования графа.

При обнаружении ошибки программа выводит соответствующее сообщение.
